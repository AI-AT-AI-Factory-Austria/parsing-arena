Open Source PDF Parsing and OCR Model Picker

Yannik Gaebel · 13 November 2026

Many AI use cases start with documents. Whether you want to make internal knowledge accessible to AI or automate invoice processing, you often need to extract information from PDFs first. Parsing converts their content and structure into a format such as Markdown for further processing.

There is a wide choice of models and libraries, each with different strengths and weaknesses. There are good API solutions too. But when sensitive data needs to stay on your own infrastructure, you need a solution you can run there. Open-source models and libraries are a useful option here.

Not all PDFs are the same

Tables with merged cells, multiple columns, charts, formulas, footnotes and unclear reading order can all make extraction difficult. There is also a basic distinction: a digitally created PDF usually stores text as characters. A scan starts as an image and can gain a searchable text layer through OCR, or optical character recognition.

Different methods handle this in different ways:

  • pypdf extracts text that is already stored in the file. It cannot read scans that have no text layer.

  • docTR reads text from pixels: it locates words on the page and recognises their characters.

  • Docling Standard combines embedded PDF text with models for layout and table structure, using OCR where needed.

  • Granite Docling 258M processes a page image and generates both text and structure. It is a vision-language model.

  • Unlimited-OCR 2 can read several page images together, using context across page breaks.

The best method therefore depends heavily on your own documents. A solution that handles simple invoices well may not work equally well on scientific papers with tables and formulas.

Compare models on your own documents

That is why we built Parsing Arena: a tool for testing 24 open-source models and methods on your own documents. The selection ranges from lightweight text extraction to larger vision-language models and includes different presets for some frameworks.

Upload a document, select the methods and pages you want to test, and start the comparison. The original appears on the left and each model's output on the right, either rendered or as Markdown. You can switch directly between models. The results table also shows processing time per page, helping you compare the quality and speed that suit your application.

Optional automated judging

Outputs can also be evaluated automatically: LlamaParse Agentic Plus provides the reference, and Mistral compares the results against it as an LLM-as-a-Judge. Each model's result is rated Excellent, Pass or Fail. Any detected errors are briefly explained. Since the reference can also contain errors, checking the original remains important.

This feature is switched off by default. When enabled, the full document is sent to LlamaParse; Mistral receives the extracted texts. This transfer must be explicitly confirmed before the run starts.

Fixed presets as a starting point

Frameworks such as Docling and Marker offer many ways to adapt a pipeline to your own documents. Parsing Arena uses fixed presets so you can try the methods without extensive configuration.

This is useful for quickly finding a suitable solution that produces usable results out of the box. It does not show everything a framework can do, though. With Docling, for example, the choice of OCR engine, language settings or table recognition options can make a difference. A first test with our presets is therefore a starting point for your own pipeline.
